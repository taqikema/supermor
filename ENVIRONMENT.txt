SUPERMOR independent core: verified numerical environment
========================================================

Environment reconstruction
--------------------------
The root environment.yml is the installation entry point. It pins Conda
package versions and builds for linux-64, plus official COMET/custEM Git
commits and the small Python runtime dependency set in its pip section.
After creating and activating it, install this repository with:

  conda env create -f environment.yml
  conda activate supermor
  python -m pip install --no-deps --no-build-isolation .

The original independent-package migration used a separate environment
reconstructed from 377 exact Conda artifact records. That explicit URL and
checksum format has been archived outside the repository and replaced by
the root YAML recipe. CORE_VALIDATION.json distinguishes the migration
checks from the YAML reconstruction and records completed results. Conda
may reuse its download cache; a fresh environment does not establish a
cold-cache network reconstruction. The existing cust_env is not modified.
No installed environment is bundled.

Official custEM commit: be0ef8729761a7eae32ababc8b362514d84f5f0a
Official COMET commit: 53e094f535b6fa67e5f55ef730233771c5d034a8
COMET is needed by the upstream profiler's import even when profiling is off.
Both packages are external and unmodified. Installed upstream Python files
were compared with the official checkout. CORE_VALIDATION.json records the
completed source, installed-wheel, MPI and numerical checks.

Rebuild and validation
----------------------
Run the installation and test commands in the root README.txt. Activate the new
Conda environment (or use conda run); invoking its Python alone does not set
the pkg-config/compiler paths required by DOLFIN JIT. Use one BLAS/OpenMP
thread per MPI rank for the recorded tests. Keep PYTHONPATH free of old
research custEM checkouts. Default source tests load only core/supermor;
SUPERMOR_TEST_INSTALLED=1 tests the installed wheel from outside the repo.

The YAML recipe is specific to linux-64 and intentionally retains the
compatible numerical/compiler/rendering stack. It is not a minimal plotting
environment or a portable lock for other operating systems. A venv and the
root requirements.txt alone cannot supply the ABI-matched numerical stack.
That requirements file lists candidate future plotting/data packages only;
the implemented core uses pyproject.toml plus environment.yml.

Small-model acceptance
----------------------
Serial and MPI2 execute independent UFL/dense reference checks for P1/P2,
scalar/VTI, real official MOD/H5 construction, source/receiver operators and
solver failure handling. Actual original-equation residual <=1.01e-6;
independent reference/DFOM residual <1e-10; mass-norm and E/H errors <1e-3.
At fixed MPI size, old/new fields and E/H must agree within relative L2
1e-10 plus absolute 1e-12 and retain algorithm summaries. Across MPI sizes,
compare physical E/H only at relative L2 1e-4 plus absolute 1e-12.

P1 supports all four methods. P2 supports SUPERMOR residual_mr without
residual correction; DFOM/RK are retained at the operator interface only.
P2 IFOM and P2 chain/correction are explicitly unsupported. VTI assignment
must follow upstream build_var_form, never precede a subsequent rebuild.
Core validation does not certify the large paper cases or timing/memory.

Mesh generation
---------------
Use mesh_gen/generate.py with the activated numerical environment. The
existing WSL cust_env can run mesh generation without installing a package
inside this repository. TetGen 1.6.0 and pyGIMLi 1.5.0 are the recorded mesh
tools. The block emg3d mesh-only entry uses NumPy and does not import the
emg3d forward solver. The current migration checks and their environment
scope are recorded in MESH_VALIDATION.json; they are separate from the core
solver reconstruction in CORE_VALIDATION.json.

Drawing environment
-------------------
Figures using sumor_paper_figure_style.py require Times New Roman. Set
SUMOR_PAPER_FONT_DIR to an available font directory, or explicitly document
any supported substitution. The block cross-validation plotter separately
preserves its supplied DejaVu Sans layout. The VTK
survey renderer also needs portable font/path settings and an appropriate
headless or display-backed rendering environment. Do not assume the
original /mnt/c/Windows/Fonts or /mnt/d paths exist on a reader's system.

Figure 7 uses VTK, Pillow and a complete VTM scene with its referenced
VTU/VTP files. Figure 11 currently uses segyio and source SEG-Y files;
providing a frozen section.npz and a dedicated section plotter can remove
that dependency from the redraw-only route after the new entry is tested.

Hardware and measurements
-------------------------
List resources separately for plotting, a small solver check and the full
published benchmarks. Do not describe the full HPC allocation as the
minimum needed for every task. For each benchmark record MPI ranks,
threads per rank, thread-library settings and launch/affinity commands.

Document complete-forward timing boundaries and the aggregate peak-PSS
sampling convention. Published performance inputs preserve the reported
measurements; reruns on other machines need not have identical timings.
Document numerical acceptance thresholds and the expected output shapes.

Before publication
------------------
The core has a version/build-pinned platform-specific recipe and verification
records in CORE_VALIDATION.json.
The full-case and redraw routes still require their own input recovery,
execution and resource checks before a complete paper release.
